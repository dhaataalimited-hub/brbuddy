BRBuddy, plumbing first

Where things live and how they connect. BRBuddy keeps a Mac awake while an AI coding agent works, covers every screen with a companion ("BRB") that needs Touch ID or the login password to dismiss, and shows what the agent is doing. Everything runs locally; there is no server. It ships outside the App Store and isn't sandboxed.

What talks to what

Three targets. BRBuddyCore holds pure logic and system wrappers with no UI and is what the tests cover. BRBuddy is the app: SwiftUI views, AppState and the controllers it owns. brbuddy-hook is a tiny helper that agents run. Package dependencies: KeyboardShortcuts (MIT) for the global shortcut and Sparkle (MIT-style) for automatic updates. Boxes link to the journey that uses them.

Menus and screens

Menu: Keep Mac awake · "Kept awake while your agent works" · BRB now (⌃⌥⌘B) · "BRB starts after N min away" · "Walk-away: …" · agents list (up to six sessions; clicking one jumps to its Terminal/iTerm2 tab or app window) or "Set up agents…" · Settings… · Quit BRBuddy.

Away screen phases (AwayController.Phase): resting → any key, click, scroll or mouse move → unlocking → back to resting after 30 s without input. Any phase → locking for real when AwayPolicy says so (3 failures or 60 min by default), which shows the reason for 2 s, calls the real lock, then takes the away screen down behind it.

Agents: setup and status

Agent hook → helper (main.swift) → AgentSocket → AgentEventListener → AgentMonitor → AgentTracker → AppState
  • Six agents; per-agent config shapes; our entries found by the helper's name, backups saved once.
  • Helper prints nothing, exits 0, gives up within about 2 s.
  • Timeouts: working 30 min, waiting 4 h, finished 15 min.

Walk-away lock

SettingsView → ProximityMonitor → ProximityTracker → AppState → BRB or ScreenLocker
  • Thresholds −62 / −74 / −86 dBm; away after 10 s weak or 60 s silent; back at threshold + 6 dB.

Battery on the away screen

AwayController → BatteryMonitor → BatteryWatch → BatteryReaction → BatteryBadge + CompanionView (CritterView, BatteryFlair)
  • Read once a second, only while BRB is up; desktop Macs show nothing.
  • Plug-in cheers and unplug surprise last 6 s and change the mood; low (≤20%) sweats, critical (≤10%) wobbles, Low Power Mode plays in slow motion.
  • Agent waiting or someone unlocking keeps the speech bubble.
  • On battery the body holds still and only the face moves; packs can ship a still sheet (stillSpritesheetPath).

Files

~/Library/Application Support/BRBuddy/: agents.sock (0600, recreated at launch), bin/brbuddy-hook (helper copy), Companions/<folder>/ (packs). Agent setup edits the agent's own file (~/.claude/settings.json, ~/.codex/hooks.json plus config.toml, ~/.gemini/settings.json, ~/.cursor/hooks.json, ~/.gemini/config/hooks.json, ~/.grok/hooks/brbuddy.json) after saving <file>.brbuddy-backup. Passwords are never stored; agent sessions live in memory only.

Threads

Swift 6 language mode; app types are main-actor. Off the main thread: password checks, pack frame cutting, process scans, tmux and Accessibility capture, socket reads (own serial queue). Touch ID results are ignored if their LAContext has been replaced.

Debug only

BRBUDDY_START_AWAY=<seconds>, BRBUDDY_SNAPSHOT_DIR and BRBUDDY_COMPANION_SHEET, BRBUDDY_BATTERY_SHEET, BRBUDDY_BOOP_SHEET, BRBUDDY_STUDIO_SNAPSHOT and BRBUDDY_FAKE_BATTERY in debug builds; compiled out of release.

Features and support

The full plain-English guide is docs/support-guide.md. The questions that come up most:

BRB didn't start on its own.
It only auto-starts while the Mac is kept awake (by hand or for an agent) and after the idle minutes with no input. Mouse jigglers and remote-desktop tools reset the idle clock.
The menu doesn't show my agent.
Press Set up in Settings → Agents, then start a new agent session. Desktop apps can't report status.
The terminal panel says "Nothing to show".
It lists why: tmux missing or not running, Accessibility not allowed, or no agent events yet.
Accessibility was forgotten after an update.
Ad-hoc builds change signature each build; toggle BRBuddy off and on in Privacy & Security → Accessibility. Developer ID builds fix this.
The away screen doesn't show the battery.
Check Settings → Away Screen → Battery; it applies next time BRB starts. Desktop Macs have no battery.
Walk-away fires too early or late.
Change "Away means" (Near / Room / Far) and test a few times; thresholds aren't tuned on real devices yet.

Glossary

BRB
The away screen (Away mode).
Assertion
An IOKit power assertion: macOS's switch for "don't sleep".
Escalation
Handing off from BRB to the real macOS lock screen.
Hook
A command an agent runs at points in its work (prompt sent, tool used, stopped).
Helper
brbuddy-hook, the command BRBuddy's hooks run.
Session
One agent conversation, tracked by its ID.
Pack
A community companion in the Codex pet format.
Mirror
The read-only terminal panel on the away screen.
RSSI
Bluetooth signal strength in dBm; closer to 0 is nearer.
Hysteresis
Needing a clearly stronger signal to count as back than to count as gone.
